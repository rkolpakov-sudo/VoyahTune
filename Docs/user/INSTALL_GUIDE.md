## 1. Что такое VoyahTune и какие есть комплекты

VoyahTune (Open Voyah) — система приложений и установочных скриптов для головного устройства Voyah Free: восстановление режимов вождения/энергии/рекуперации после пробуждения, автосвет, сервисный режим дворников, прогрев батареи, Direct Apollo и (в full) Frida-функции.

| Возможность | light | full |
|-------------|:-----:|:----:|
| Режимы, автосвет, дворники, прогрев, Direct Apollo | ✅ | ✅ |
| Frida, сплиты, док, кнопки руля, boot-hook `load.bin` | ❌ | ✅ |
| Требует `adb root` и записи в `/system` | ✅ | ✅ |
| Обновление поверх уже установленной версии (настройки сохраняются) | ✅ | ✅ |

**Какой брать:**

- **full** — полный функционал (Frida, freeform, док, руль). Основной рекомендуемый комплект.
- **light** — без Frida и boot-hook: только режимы и удобства, меньшее вмешательство в систему.

> APK и скрипты лежат **плоско в корне распакованного ZIP** (не в подпапке `Releases` — это только вывод сборки `make_release.sh`, в git его нет). Скачивайте **целиком один ZIP** (full **или** light), не отдельные файлы.

## 2. Безопасность — прочитайте до начала

1. Автомобиль **полностью остановлен**, селектор **P**, стояночный тормоз **включён**.
2. **Не** выполняйте установку во время движения.
3. **Не** отключайте питание и USB во время установки и перезагрузки.
4. Используйте только **официальный полный релиз**; не смешивайте файлы разных версий.
5. Установщик может выполнить `disable-verity` — это изменяет системный раздел. Возможны последствия для гарантии/OTA — оцените риск заранее (см. также `Docs/user/safety.md`).
6. При сообщении **`!!!`** или **«Do not reboot»** — **не перезагружайте** ГУ, пока не восстановите ADB и не повторите тот же скрипт успешно.

## 3. Что понадобится

| Позиция | Требование |
|---------|------------|
| Кабель | **Только USB Type-A ↔ Type-A**, USB 2.0. Type-C ↔ Type-A и Type-C ↔ Type-C **не подходят**. Допустим переходник или USB-хаб. |
| Компьютер | Windows 10/11 (BAT + `adb.exe` в комплекте) или macOS/Linux (нужен системный `adb`). |
| Права ГУ | USB debugging; установщик запросит `adb root`. |
| Папка | Короткий путь без пробелов: `C:\VoyahTune` или `~/Downloads/VoyahTune`. |
| Время | 10–20 минут + две перезагрузки (см. §8). |
| Комплект | Целиком ZIP full **или** light + при желании отдельно DNS-скрипт. |

## 4. Подготовка (общая)

### 4.1. Распаковка

1. Распакуйте ZIP **полностью** в отдельную папку.
2. **Не** запускайте файлы из окна архиватора.
3. Не перемещайте отдельные файлы из комплекта и не подмешивайте APK/скрипты из другой версии.

Пример содержимого (full, упрощённо):

```
VoyahTune/
├── install.bat / install.sh / install-tui.bat / install-tui.sh
├── remove.bat / remove.sh
├── native.apk, restore_mode.apk, load.bin, *.js, voyahtune.load.*
├── adb.exe, AdbWinApi.dll, AdbWinUsbApi.dll   ← Windows
├── README.txt
└── backup/                                     ← появится после установки
```

### 4.2. Подключение ГУ

1. Авто стоит, P, ручник.
2. Подключите кабель **Type-A ↔ Type-A** к диагностическому порту ГУ и компьютеру.
3. Разблокируйте головное устройство.
4. При запросе **«Разрешить отладку по USB?»** — подтвердите (галочка «Всегда…» — по желанию).

## 5. Проверка ADB — базовый тренажёр (без изменений)

Перед установкой убедитесь, что ADB «видит» машину.

**Windows** (в папке релиза, cmd):

```bat
adb.exe devices
```

**macOS / Linux:**

```bash
adb devices
```

**Ожидаемый результат:**

```
List of devices attached
<серийный_номер>    device
```

| Состояние | Что делать |
|-----------|------------|
| Пустой список | Другой кабель Type-A↔A, другой USB-порт (желательно не хаб), драйвер Windows, режим отладки, переподключение. |
| `unauthorized` | На ГУ подтвердите RSA-ключ USB debugging. |
| `offline` | Переподключите кабель; `adb kill-server` → `adb start-server`. |
| Несколько строк | Отключите лишние Android/эмуляторы; либо (macOS/Linux, TUI) `ADB_SERIAL=<serial> ./install-tui.sh` — TUI экспортирует `ANDROID_SERIAL` для движка; при ручном запуске `adb -s <serial> ...`. |
| `adb` не найден | Windows: запуск из папки релиза (рядом `adb.exe`). macOS: `brew install android-platform-tools`. |

Если `device` есть — можно к §6 или §7.

## 6. Установка: Windows

### 6.1. Рекомендуемый путь: интерактивное меню (`install-tui.bat`)

На Windows **рекомендуется** дважды щёлкнуть `install-tui.bat` (preflight, лог `install.log`, verify, remove, DNS):

```bat
install-tui.bat
```

Меню (5 пунктов): **Install** → **Verify** (read-only) → **Remove** (restore из `backup/`) → **Yandex DNS** → **Exit**. Лог `install.log` рядом. При неполном комплекте или отсутствии устройства TUI останавливается **до** мутаций (exit 3).

> **Только full:** `install-tui.*` и `verify_post_install.*` входят в комплект **full**. В **light** их нет — используйте `install.sh` / `install.bat` (§6.2) и проверяйте по §10.

### 6.2. Non-interactive путь (`install.bat`)

Для автоматизации/скриптов без вопросов:

1. Откройте **cmd** (или PowerShell) → перейдите в папку релиза:

   ```bat
   cd /d C:\VoyahTune
   ```

2. Запустите:

   ```bat
   install.bat
   ```

   Скрипт **не задаёт вопросов** и не ждёт клавиш (удобно для автоматизации; ошибки видны в окне cmd).

3. Следите за выводом. Возможны **перезагрузки** (§8).
4. Дождитесь строки:

   ```text
   Installation complete.
   ```

5. Дождитесь **финальной** загрузки ГУ. **Не** открывайте VoyahTune до её завершения.
6. (Опционально) DNS: §9.

### 6.3. Если окно BAT закрылось мгновенно

1. Откройте cmd → `cd /d C:\путь\к\VoyahTune`.
2. Запустите `install.bat` вручную.
3. Последняя строка покажет реальную ошибку.

> В BAT специально **нет** `pause`: они не ждут клавиатуру на сервере/при перенаправленном stdin.

### 6.4. Что нельзя делать во время установки

- Не выдергивать USB и не гасить питание.
- Не закрывать cmd, пока не `Installation complete` (или явная `!!!` + инструкция).
- При `Do not reboot` — **не** перезагружать до успешного повторного запуска.

## 7. Установка: macOS / Linux

### 7.1. ADB

```bash
brew install android-platform-tools   # macOS
# или apt/dnf/pacman — пакет adb/android-tools
adb version
```

### 7.2. Подготовка прав

```bash
cd ~/Downloads/VoyahTune
chmod +x install.sh remove.sh install-tui.sh verify_post_install.sh 2>/dev/null
```

> `install-tui.sh` и `verify_post_install.sh` — **только в full**; в light `chmod` для них молча не применяется.

### 7.3. Запуск

**Рекомендуемый путь — TUI (full):**

```bash
./install-tui.sh
# флаги:
./install-tui.sh --dry-run          # только проверки, без изменений
./install-tui.sh --yes              # без лишних вопросов
./install-tui.sh --non-interactive  # полный non-interactive
```

**Non-interactive / light:**

```bash
./install.sh
```

В конце появится выбор — ставить ли Yandex DNS (§9). В light запускайте обычный `./install.sh` (TUI в комплект не входит).

### 7.4. macOS: «файл из неизвестного источника»

Не отключайте защиту целиком. Варианты:

1. System Settings → Privacy & Security → разрешить конкретный файл; **или**
2. Снять quarantine **только** с папки релиза:

   ```bash
   xattr -dr com.apple.quarantine /путь/к/VoyahTune
   ```

## 8. Сколько перезагрузок и что ждать

Планируйте **две** перезагрузки (полный комплект):

| # | Когда | Что происходит |
|---|--------|----------------|
| **1 (возможная)** | После `disable-verity`, если `/system` ещё read-only | Применение verity; установщик ждёт полной загрузки и продолжает сам |
| **2 (финальная)** | В конце установки (`Installation complete`) | Поднимаются boot-hook (full), priv-app, freeform; **сервис VoyahTune стартует только после неё** |

**Если `/system` сразу стал записываемым** — первой перезагрузки может не быть; фактически одна финальная. Планировать всё равно надо на две.

### После финальной перезагрузки

1. Дождитесь полной загрузки интерфейса.
2. Откройте **VoyahTune**.
3. Проверьте, что сервис отвечает (кнопка «Применить», виджеты) — см. §10.
4. При необходимости установите DNS (§9).

### Установка «оборвалась» между перезагрузками

- Восстановите ADB (`adb devices` → `device`).
- Запустите **тот же** `install.sh` / `install.bat` **из той же папки** — операции идемпотентны (повторный запуск безопасен).
- **Не** удаляйте папку `backup/`.

## 9. Yandex DNS (опционально)

DNS **не входит** в основную установку. Ставится **после** успешной основной установки и загрузки ГУ.

| ОС | Как запустить |
|----|----------------|
| Windows | `install-yandex-dns.bat` (отдельный файл, после `install.bat`) |
| macOS/Linux | выбор в конце `./install.sh` |

**Смысл:** интернет в режиме белых списков для сервисов, которые в эти списки входят.

**Чужой/битый DNS-overlay:** скрипт **не** перезаписывает чужой overlay. Порядок:

1. `remove.bat` / `./remove.sh` из **того же** комплекта.
2. Перезагрузка.
3. Снова основной `install.*`.
4. Затем DNS-скрипт.

При `broken/inconsistent state` — тот же цикл.

## 10. Проверка после установки

Чек-лист (5 минут):

- [ ] `adb devices` → одно устройство `device` (если кабель ещё подключён).
- [ ] После **финальной** перезагрузки открывается **VoyahTune** без крэша.
- [ ] «Применить» (режимы) — кнопка не «залипает» навсегда; после цикла разблокируется (таймаут ~12 с — страховка).
- [ ] Режим на приборке соответствует выбранному после «Применить» / пробуждения.
- [ ] Автосвет / дворники (если включали) реагируют.
- [ ] **full:** сплиты/док/кнопки руля — при необходимости.
- [ ] Удалось ли при желании выгрузить логи из «Логирование» (share).

**Сервис не стартовал:**

1. Убедились, что была **финальная** перезагрузка (не только первая).
2. Повторите `install.*` из той же папки.
3. См. §11 (`root`, `/system` RO, `!!!`).

**Опционально (TUI):**

```bash
./verify_post_install.sh    # или verify_post_install.bat
```

Ненулевой код = есть проблема; смотрите вывод.

## 11. Типовые сложности и решения

### 11.1. ADB и подключение

| Симптом | Причина | Решение |
|---------|---------|---------|
| `adb.exe is not recognized` / `adb: command not found` | Не та папка / нет platform-tools | Windows: запуск из папки релиза (`adb.exe` рядом). macOS: `brew install android-platform-tools`, **новый** Terminal. |
| Пустой `adb devices` | Кабель/порт/драйвер | Только Type-A↔A; другой порт; драйвер Windows; `adb kill-server && adb start-server`. |
| `unauthorized` | Не подтверждён RSA | Разблокировать ГУ → подтвердить отладку по USB. |
| `offline` | Обрыв | Переподключить; kill/start-server. |
| Ожидание на `wait-for-device` | Устройство пропало | Если ждёт дольше ~30–60 с — безопасно закрыть окно **до** начала копирования → починить ADB → **повторить** установку сначала. |
| Несколько устройств | Эмуляторы/другие гаджеты | Отключить лишние; sh-TUI: `ADB_SERIAL=<serial> ./install-tui.sh`; иначе `adb -s <serial>`. |

### 11.1b. Preflight ДО записи в `/system` (Apollo / WRITE_CANBUS)

Установщик останавливается **до** любых изменений системы, если preflight не пройден. Ничего не «сломано» — `/system` не тронута.

| Симптом в выводе | Что это | Что делать |
|------------------|---------|------------|
| `!!! Владелец com.qinggan.permission.WRITE_CANBUS не определён однозначно` | dumpsys не отдал `sourcePackage` (бой/ограничение прошивки) | Повторить после переподключения; сверить прошивку с матрицей; **не** обходить fail-closed вручную. |
| `!!! com.qinggan.permission.WRITE_CANBUS уже принадлежит <пакет>` | Право занято сторонним CanBus-пакетом | Удалить/заменить несовместимый пакет (см. `Packaging/README.md`) или оставить как есть, если пакет штатный — **не** продолжать установку «поверх». |
| `!!!` про Apollo safe-keys / VehicleSetting hook OFF | Fail-closed ключи Apollo не в ожидаемом состоянии | Следовать тексту в консоли; обычно — повтор install из той же папки после устранения причины. |
| TUI: `Preflight не пройден — install.sh НЕ запускался` | Локальный bundle/adb-check до мутаций | Распаковать ZIP заново / починить ADB → повторить. |

### 11.2. BAT / запуск скриптов

| Симптом | Причина | Решение |
|---------|---------|---------|
| Окно закрылось мгновенно | Ошибка без pause | `cmd` → `cd /d ...` → `install.bat` вручную; читать последнюю строку. |
| «Access is denied», антивирус | Карантин / incomplete extract | Распаковать заново; карантин AV; не брать BAT/APK со стороны. |
| Отсутствует обязательный файл | Неполный комплект | Распаковать ZIP целиком; не выносить отдельные файлы. |
| Скрипт «тихо» вышел 0, но что-то не так | Exit-код не всегда отражает `!!!` в тексте (I19; частично закрыт D3) | Смотреть текст `!!!` в выводе, не только `%ERRORLEVEL%`; при сомнении — `verify_post_install.*` (full) и повтор `install.*`. |

### 11.3. Права root и запись в `/system`

| Симптом | Причина | Решение |
|---------|---------|---------|
| `adbd cannot run as root` | Прошивка/порт не даёт root | Установку продолжать **нельзя**. Проверить поддерживаемую прошивку и **диагностический** USB-порт. |
| `/system remains read-only`, `I/O error`, EROFS, remount fail | verity / EROFS / locked bootloader | Установщик уже пробует disable-verity → reboot → remount. Вручную: `adb disable-verity` → `adb reboot` → дождаться → `adb root` → `adb remount`. Если всё равно RO — прошивка/загрузчик не даёт писать системный раздел. |
| `!!! /system ОСТАЁТСЯ read-only — установка прервана (ничего не тронуто)` | То же | Ничего не изменено. Устранить причину RO и повторить. |

### 11.4. Сбои посреди установки

| Симптом | Решение |
|---------|---------|
| USB оборвался при копировании | Восстановить ADB → **тот же** скрипт, **та же** папка. Не удалять `backup/`. |
| `!!!` + `Do not reboot` | **Не** перезагружать. Восстановить ADB → повторить скрипт → после успеха можно перезагружаться. |
| Частичный boot-hook / «incomplete RC» (full) | Следовать тексту в консоли (обычно: не перезагружать, повторить installer). |
| Ошибка `pm install` / RestoreMode | Убедиться в месте на кабеле/памяти; повторить `install.*` (операции идемпотентны). |
| light: `Не удалось записать Native.apk…` | Установка **прервана** (файл не считается установленным). Проверить RO/место/кабель → повторить. |

### 11.5. После установки «не работает»

| Симптом | Решение |
|---------|---------|
| Нет иконки / сервис не отвечает | Ждали только **первой** перезагрузки? Нужна **финальная**. Повторить install. |
| Режимы не восстанавливаются | См. FAQ в `readme.md`: шторка/настройки — часто **OEM-баг** (4.1/7.1 OD), приборка слушает CAN корректнее. |
| Панель быстрого доступа «электро+эко», на приборке нормально | Не баг VoyahTune (см. `readme.md` FAQ). |
| Долгий запуск после снятия с охраны | По FAQ — не длительные init-процессы приложения; вероятно, реакция ГУ на новое ПО. |
| macOS Gatekeeper | §7.4. |
| Сплиты/док/руль не работают | Нужен **full** + финальная перезагрузка; light этих функций не содержит. |

### 11.6. Ошибки в развёрнутом виде (кратко из README.txt)

```text
"adb.exe is not recognized"     → папка релиза / platform-tools
Окно BAT закрылось              → cmd + ручной запуск
"unauthorized" / нет устройств  → подтверждение RSA, кабель, kill-server
"adbd cannot run as root"       → root недоступен — стоп
"/system remains read-only"     → disable-verity / reboot / remount / EROFS
Ошибка копирования / мало места → кабель, место, целостность ZIP → повтор install
Установка готова, нет ребута    → перезагрузить ГУ вручную, не открывать app до загрузки
```

## 12. Удаление и откат

1. Используйте `remove.bat` / `./remove.sh` **из той же папки релиза**, где создана `backup/`.
2. **Не** удаляйте и не подменяйте `backup/` до конца отката.
3. Удаление восстанавливает системные файлы (и DNS, если ставился этим комплектом), затем перезагружает устройство.
4. Если ADB прервался: не смешивать версии, не трогать `backup/`, повторить **тот же** `remove.*`.
5. При `Do not reboot` — не перезагружаться до успешного отката.

**Порядок «с нуля» после сбоя (из рекомендаций проекта):**  
`remove.*` → перезагрузка → `install.*`.

## 13. Частые вопросы (FAQ)

**Q: Полная или light?**  
A: Полный функционал и проверенный сценарий — **full**. Нужно минимально трогать систему без Frida/boot-hook — **light**.

**Q: Одна перезагрузка или две?**  
A: Обычно **две**: первая — если после disable-verity `/system` остался RO; вторая — финальная, после неё стартует сервис.

**Q: Какой кабель?**  
A: **Только USB Type-A ↔ Type-A (USB 2.0).** Type-C не подходит.

**Q: Ставится поверх старой версии?**  
A: Да, `install` рассчитан на обновление; настройки RestoreMode/Native сохраняются (`adb install -r`, push APK без сноса data). Полная чистка — через `remove` + повторный install.

**Q: Работает ли на моей прошивке (рест/дорест/PI/OD)?**  
A: Команды уходят в CAN; важно, принимает ли их VCU. Эталон тестов — рестайл 2024 / Sport+ 2026; остальное — по отзывам (`docs/audit/compatibility-matrix.md` — черновик).

**Q: Можно ли удалить?**  
A: Да, `remove.*` из той же папки релиза + `backup/`.

**Q: Ставить DNS сразу?**  
A: DNS — **отдельный** шаг **после** успешной основной установки.

## 14. Отчёт об ошибке

Приложите:

1. Версию архива и **full/light**.
2. Windows или macOS (версию).
3. Полный вывод скрипта **начиная с первой строки `!!!`**.
4. Вывод `adb devices`.
5. Версию VoyahOS и модель автомобиля.
6. На каком шаге упало USB/питание (если было).

**Не публикуйте** серийные номера, персональные данные и содержимое `backup/`.
