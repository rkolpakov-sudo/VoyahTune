0029| ### 1.2. Назначение проекта
0030| 
0031| **VoyahTune** (эволюция из `RestoreMode`) — системное Android-приложение
0032| для автомобилей **Voyah Free**, которое:
0033| 
0034| - Восстанавливает настройки режимов вождения после пробуждения автомобиля
0035| - Добавляет автоматизации (автосвет, дворники, музыка, прогрев батареи)
0036| - Модифицирует системный интерфейс (сплиты, док, кнопки руля)

0211| ## 3. КРИТИЧЕСКИЙ АНАЛИЗ ИСХОДНОГО ПЛАНА
0212| 
0213| ### 3.1. Фундаментальные проблемы
0214| 
0215| #### 3.1.1. План построен на предположениях
0216| 
0217| **Проблема:** План рефакторинга был составлен на основе анализа
0218| установочных скриптов и внешней структуры репозитория, но НЕ на основе
0219| чтения исходного кода основных компонентов.
0220| 
0221| **Не прочитано:**
0222| - Код `Native/` (системное приложение)
0223| - Код `RestoreMode/` (пользовательское приложение)
0224| - Логика Frida-скриптов
0225| - Структура CAN-команд и протокол взаимодействия
0226| 
0227| **Последствия:**
0228| - Предложенная модульная структура может оказаться несовместимой
0229| - Рефакторинг потребует полного переписывания
0230| - Будет потерян критический функционал
0231| 
0232| **Решение:** Перед началом любого рефакторинга необходимо провести
0233| полный код-ревью всех исходников.
0234| 
0235| #### 3.1.2. Игнорирование специфики автомобильного ПО
0236| 
0237| **Проблема:** План рассматривает VoyahTune как обычный Android-проект,
0238| применяя стандартные практики рефакторинга.
0239| 
0240| **Но это автомобильное ПО, которое:**
0241| - Работает в критической системе (управление режимами вождения)
0242| - Взаимодействует с физическим оборудованием (CAN-шина, VCU)
0243| - Должно работать безотказно
0244| - Зависит от конкретной версии прошивки автомобиля
0245| 
0246| **Несовместимость стандартных практик:**
0247| 
0248| | Стандартная практика | Проблема в контексте авто |
0249| |---------------------|---------------------------|
0250| | Модульные тесты с моками | Невозможно имитировать CAN-шину |
0251| | Покрытие кода тестами | Критические пути только на реальном авто |
0252| | Частые релизы | Каждый релиз требует физического тестирования |
0253| | Рефакторинг "на лету" | Любое изменение может нарушить работу авто |
0254| 
0255| **Решение:** Для автомобильного ПО приоритет должен быть на
0256| минимальных, проверяемых изменениях с обязательным тестированием
0257| на реальном автомобиле.
0258| 
0259| #### 3.1.3. Недооценка сложности установщика
0260| 
0261| **Проблема:** План предлагает разбить `install.sh` (646 строк) на модули,
0262| но не учитывает, что этот скрипт:
0263| 
0264| 1. Управляет состоянием через несколько перезагрузок
0265| 2. Работает с `disable-verity`, изменяя загрузочный образ
0266| 3. Создает атомарные операции через промежуточные файлы
0267| 4. Обрабатывает множество сценариев ошибок с откатом
0268| 
0269| **Риск:** Разбиение на модули может нарушить атомарность операций.
0270| Между вызовами модулей может произойти сбой, и система останется
0271| в промежуточном состоянии.
0272| 
0273| **Решение:** Установщик нужно документировать и тестировать в текущем виде.
0274| Любые изменения должны быть минимальными и не нарушать атомарность.
0275| 
0276| ### 3.2. Технические риски
0277| 
0278| #### 3.2.1. Несовместимость с обновлениями прошивки
0279| 
0280| **Проблема:** Автомобили Voyah получают регулярные обновления прошивки.
0281| Каждое обновление может:
0282| - Изменить структуру системных файлов
0283| - Изменить права доступа
0284| - Изменить поведение CAN-шины
0285| - Заблокировать `disable-verity`
0286| 
0287| **Известные различия:**
0288| - На прошивке 4.1 ОД восстанавливается энергия и рекуперация
0289| - На прошивке 7.1 ОД восстанавливается только рекуперация
0290| 
0291| **Решение:** Создать матрицу совместимости версий прошивок.
0292| 
0293| #### 3.2.2. Зависимость от Frida
0294| 
0295| **Проблемы:**
0296| 1. Версионная совместимость: `frida-inject-16.2.1-android-arm64`
0297|    может стать несовместимым с новыми версиями Android
0298| 2. Стабильность инъекций: инъекции в системные процессы могут
0299|    вызывать падение процессов
0300| 3. Обнаружение: автомобильные системы могут блокировать инъекции
0301| 
0302| **Решение:** Минимизировать использование Frida, перейти на прямые
0303| системные вызовы где возможно.
0304| 
0305| #### 3.2.3. Проблема с `disable-verity`
0306| 
0307| **Риски:**
0308| - Отключает проверку целостности системы
0309| - Делает систему уязвимой
0310| - Может быть необратимым на некоторых устройствах
0311| - Может лишить гарантии
0312| 
0313| **Решение:** Явно предупреждать пользователей о рисках.
0314| 
0315| ### 3.3. Проблемы процесса разработки
0316| 
0317| #### 3.3.1. Отсутствие тестовой инфраструктуры
0318| 
0319| **Проблема:** Невозможно:
0320| - Имитировать CAN-шину без реального авто
0321| - Автоматизировать тестирование
0322| - Проводить регрессионное тестирование
0323| 
0324| **Решение:** Создать минимальную тестовую инфраструктуру:
0325| - Чек-лист для ручного тестирования
0326| - Скрипт автоматической проверки базовой функциональности
0327| - Матрица совместимости версий прошивок
0328| 
0329| #### 3.3.2. Отсутствие стратегии версионирования
0330| 
0331| **Проблема:** Нет:
0332| - Четкой схемы версионирования
0333| - Гарантии совместимости между версиями
0334| - Механизма отката на предыдущую версию
0335| - Миграционных скриптов
0336| 
0337| **Решение:** Внедрить семантическое версионирование (SemVer).
0338|

0341| #### 3.4.1. Отсутствие модели угроз

0343| **Потенциальные угрозы:**
